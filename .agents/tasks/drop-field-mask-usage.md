# Stop applying `FieldMask` in `SelectMessagesByQuery`

Follow-up to SpineEventEngine/core-jvm#1679 ("Drop support of `FieldMask` in querying and
subscription APIs"). It was merged on 2026-10-03 as `d6a73060f96` and published as
`2.0.0-SNAPSHOT.560`. There, `io.spine.server.storage.FieldMaskApplier` is `@Deprecated` and
does nothing. The fixture `DelegatingRecordStorageTest` asserts that storages ignore
`RecordQuery.mask()`.

## Base and precondition

- Branch `drop-support-of-field-mask` starts from `origin/master` @ `c7479084`. That base has
  repo version `.121`, core-jvm `.551`, Kotlin 2.4.10, Gradle 9.7.1, and Protobuf 4.36.0.
- A first attempt started from a stale local `master`: 38 commits behind, last fetched
  2026-06-26. It was discarded, because upstream had already done the toolchain sync, the
  `DelegatingRecordStorageTest` re-base, and the `StorageFactory`/`StorageGroup` fixes.
- core-jvm `.560` was published on 2026-10-03, after core-jvm#1679 merged. The final build
  uses `--refresh-dependencies` so that it resolves the published artifacts. Remote
  repositories precede `mavenLocal()`, so an earlier Maven Local build of the branch cannot
  shadow them.

## Mask usage inventory

`SelectMessagesByQuery` is the only usage. No other main or test source, and nothing in
`docs/`, has `withMask`, `FieldMask` parameters, or mask mentions. The "mask" in
`TableSpecs.java` is a UTF-8 bit mask and is unrelated.

Every read reaches the class along this path:

`RecordStorage.readAll(query)` → `JdbcRecordStorage.readAllRecords()` → `RecordTable.read()`
→ `ReadManyByQuery` → `SelectMessagesByQuery`.

On the published stack, no query reaches the class with a mask:

- In Base `.450`, `QueryBuilder.withMask(..)` stores nothing, and `Query.mask()` (deprecated)
  always returns `FieldMask.getDefaultInstance()`.
- The deprecated `read(id, mask)` and `readAll(ids, mask)` overloads drop the mask inside
  core-jvm, in both `RecordStorage` and `DelegatingRecordStorage`.

The removed masking branch was therefore unreachable. Keeping it would also have called the
deprecated `Query.mask()`.

## Changes

- `SelectMessagesByQuery.java`:
  - `execute()` returns the records as read;
  - `maskFields(..)` is removed;
  - the now-unused imports are removed: `FieldMask`, `FieldMaskApplier`, `NonNull`,
    `Iterators.transform`.
- `buildSrc/.../dependency/local/*.kt` versions now match core-jvm's own `buildSrc` at the merge
  commit `d6a73060f96`:

  when a change is reclassified as breaking.
- `docs/dependencies/{pom.xml,dependencies.md}` are regenerated by the build.

## Tests

No new tests are needed. A `RecordQuery` can no longer carry a mask, so there is no masked
input to test. The final core-jvm fixture dropped its query-level mask tests for the same reason.

The inherited cases that remain run on H2 (`JdbcRecordStorageTest`) and on MySQL
(`MysqlRecordStorageTest`). They check that the deprecated mask overloads return full records,
and that those overloads throw once the storage is closed.
